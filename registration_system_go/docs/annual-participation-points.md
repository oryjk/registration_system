# 年度参与积分

规则 v2（2026-10-07）：出场与表态独立。已结束、非取消的球队比赛，最终 attending 获得7分基础分；本人第一次报名、请假或主动声明不参加时，按相对可报名时刻的延迟固定表态奖励。<=1h、<=6h、<=24h、>24h分别奖励3、2.4、1.5、0.6分。请假/缺席不获得出场基础分，但有首次表态奖励；后续状态修改、取消重报和管理员修正不重算奖励。取消的比赛/球队报名组整体不计分。未表态、纯管理员补录没有表态奖励。

未来报名以比赛创建、报名组创建、报名开放、入队时间最晚值为可表态时刻，原报名窗口继续限制提交。第一次表态立即保存时间和奖励；年度汇总仍只统计已结束比赛。参加后请假只减去7分出场分，原表态奖励保留。

兼容字段 participation_confirmed_at 在v2代表首次表态时间，包含首次请假/主动不参加；early_registration_bonus为固定表态奖励，participation_rule_version在首次保存/补录时写2。积分列及SQL汇总用十分之一分的整数（70代表7分），HTTP统一除以10；年度按UTC比赛start_time转换到北京时间的年份归属，历史保留。当前荣誉只排名active成员；totals的attended_count只计算获得出场基础分的记录。

接口路由、旧出勤字段和排序保持不变：比赛participants增加team_participation_points/rank，球队members和统计增加participation_points/rank，attendance-summary增加annual_points。新小程序无需改动即可展示更新积分。

## 历史补录

`cmd/backfillparticipationpoints`默认只读预览，需明确`--before`历史截止时刻和`--apply`才会写入。目标为截止前的报名/操作且尚无首次表态奖励记录，旧库只读，通过legacy_import_mappings的报名映射精确关联；旧rs_user_activity.operation_time按用户认可的历史近似表态时间处理。旧stand=0不是表态，如果后来在Go系统中表态则使用现存updated_at（即Go统计接口operation_time），因为导入创建时间属于未表态占位，无法还原后续第一次表态。Go原生历史使用报名记录created_at还原最早报名时间，后续updated_at可能来自状态修正等操作，不能作为首次表态时间。

旧库报名窗口是北京时间墙钟，转换为UTC；审计/操作时间维持UTC。部分导入created_at等于/晚于比赛举行时间，不作为发布时间，用原报名开放时间恢复基线；忽略导入报名组的人工创建时间。旧创建事务的5秒以内反向时间差按零延迟计分，保留原操作时间；更大的反向时间差或截止后补录不授予奖励。未知/缺失时间保留基础分，已有可靠奖励不覆盖。

补录只修改首次表态时间、奖励及规则版本，不修改参赛/请假、支付、人数、created_at/updated_at；在一次事务中执行，行锁及原值比对保护并发和幂等。运行前做数据库备份，先预览再应用；重复预览应不再有可写记录。

通过环境变量配置DATABASE_URL、LEGACY_PG_URL后，在Go项目运行：

```bash
go run ./cmd/backfillparticipationpoints --before=2026-10-07T00:52:35Z --report-user=4
go run ./cmd/backfillparticipationpoints --before=2026-10-07T00:52:35Z --report-user=4 --apply
```

该截止时刻对应首次积分版本启用，只补之前的旧记录。2026-10-07只读预览：1950条候选，1922条可补，28条时间不足跳过，1449条有表态奖励。用户4在球队11的2026年积分预计196→256。上线前已验证首次请假、后续修改/取消/重报、管理员修正、年度归属和历史查询；真实数据库独立schema验证排行榜、单场/个人统计的一致性及补录幂等性。

### Go原生历史首次表态修正（2026-10-07）

首轮补录错误使用Go记录updated_at，导致用户4在9月30日比赛中9月28日发布后约5秒报名，却因10月6日的后续修改得0分奖励。修复后使用created_at，正确奖励3分，单场共10分。

已执行旧补录的数据用显式`--repair-go-history`修正：仅选择没有legacy报名映射、规则版本2、补录时间等于updated_at且created_at更早的记录。创建和修改时间均必须早于首次积分启用时刻；修复截止上限强制为2026-10-07T00:52:35Z。该时刻前尚无线上v2首次表态，结合原值条件可识别旧补录事实，保护v1真实奖励、后续线上v2奖励和旧系统映射记录。Go原生创建时间明显早于开放基线的占位记录跳过。

```bash
go run ./cmd/backfillparticipationpoints --before=2026-10-07T00:52:35Z --repair-go-history --report-user=4
go run ./cmd/backfillparticipationpoints --before=2026-10-07T00:52:35Z --repair-go-history --report-user=4 --apply
```

修复预览：14条记录恢复最早时间，其中8条奖励改变，2026年全队合计增加11.7分；用户4在球队11预计256→259、球队10预计21.5→23。数据库独立schema测试已覆盖早报名后改动、支付及状态不变、保护已确认奖励及旧库记录、重复执行无新增写入；单元测试覆盖修复截止限制。本次只修改补录工具，不需要新增schema迁移或更改小程序接口。
