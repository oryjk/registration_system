# 小程序 / H5 统一设计系统（现行规范）

**状态：当前有效。适用范围：`registration_system_mini` 的 H5 与 mp-weixin。2026-11-03 的视觉延伸按用户最新要求只实施并验收微信小程序，既有其他平台分支保留。**

本文是前端视觉与交互的唯一现行规范，优先于历史设计稿、改版实施计划及基线快照。当前采用「轻量赛事 UI」：浅色表面、柔和圆角、留白分区、清晰主次。微信端使用浅中性页面背景、独立圆角卡片与柔和阴影，内部列表保持平面；H5 沿用原样式。D 仅是方案选择时的历史代号，不用于组件命名。

旧 Neo / Soft Neo / Neobrutalism 视觉规范已废止。不得恢复粗黑描边、硬偏移阴影、800/900 常规字重、风格型组件名或 `--neo-*` token。历史文件仅用于追溯业务决策，不可据其复原旧皮肤。现行组件位于 `src/components/ui/`，样式入口为 `src/styles/design-tokens.css`，强调色配置为 `src/config/themePalettes.ts`；命名迁移已经完成。

## 设计语言

清晰、轻量、主次分明：白底（`#fffffe`）+ 海军蓝标题（`#00214d`）+ 深蓝灰正文（`#1b2d45`），默认薄荷蓝强调（`#00ebc7`），辅助 `#ff5470` / `#fde24f`；轻描边（`#e4eaf2` 线色）、柔和阴影、明显圆角。信息层级靠排版与留白表达，一处只突出一个主动作；不靠重描边、硬投影或装饰渐变制造层级。

## Token 层次

`src/styles/design-tokens.css` 按三层组织：

1. **primitive**：原始色值、透明度、圆角、阴影基色（`--ui-primitive-shadow-rgb: 24, 55, 100`）、状态语义原语；
2. **semantic**：页面/表面/文字/线色、强调、CTA、状态（success/warning/danger/neutral 的 `-fg`/`-bg` 成对）、遮罩；
3. **component**：Surface、Button、Tag、Progress、Segmented、Avatar、ActionBar 等组件契约，以及 `--now-*` 基准卡层（默认值引用语义层，主题相关项由 page-meta 覆盖）。

结构 UI 必须引用 token，不在页面和共享壳层新增散落 hex、间距或字号数值；`--app-primary` 兼容出口仅在 token 文件映射。运行时组件直接 `.vue` 导入（`src/components/ui/`）。

### 微信页面共享契约（2026-11-01）

2026-11-03 延伸：首页确认的细线图标、单 chevron、辅助灰蓝文字、纯文字主操作与轻量卡面推广至其他微信页面。共享卡面 `--ui-card-radius` 为 36rpx，`--ui-card-padding` 为 28rpx；原基础 `--ui-radius-card` 与表单等专用尺寸不机械替换。次要文案使用 `--ui-color-text-secondary`，图标使用 `--ui-color-icon-muted`（均为 `#65758b`）；状态颜色、业务信息和点击语义不变。

- 页面根节点使用 `app-theme-scope ui-card-page` 并在 scoped 样式引入 `page-surfaces.css`，只在 MP-WEIXIN 使用 `--ui-color-page-muted`，H5 原样。原生地图、海报画布和 web-view 文档不机械套用卡片。
- 独立内容优先复用 `AppSurface`：微信端 raised/outlined 默认无描边，使用 `--ui-card-padding/radius/shadow`。`flush` 由内部原生 wrapper 承担 padding；深色 hero 与确认浮层继续使用自身契约。
- 原生容器复用 `list-surfaces.css` 的 `ui-card-panel`（完整内边距）或 `ui-card-list`（横向内边距、行内控制纵向间距），需要图片贴合外层时使用 `ui-card-panel--flush`。卡面颜色使用 `--ui-card-bg`，卡间距使用 `--ui-card-gap`。
- `--ui-panel-*`、`ui-plain-panel`、`ui-soft-panel` 与 `ui-list-row` 留给卡片内部的平面分组、摘要和列表；不要将它们全局改成带阴影。嵌入内容显式保持平面，避免重复阴影和内边距。AppSurface 允许局部 `--ui-content-surface-radius/shadow` 覆盖，但仅在确有嵌入需求时使用。
- 创建、加入、帮助与发布页头复用 `AppPageIntro` 和现有 MinIO 缓存插画。间距、字号、行高、字重、图标、表单与底栏尺寸使用对应共享 token，业务请求与提交仍由父页面负责。
- 输入边界、选中状态、危险操作、确认弹窗和报名进度语义保持清晰；不把球衣颜色、业务色卡或海报画布设计值机械替换成页面 token。
- 分类比赛列表的纯箭头详情入口使用 `--ui-control-plain-bg`，不显示常驻浅底；点击尺寸继续使用 `--ui-control-min-height`，保留按压反馈。带状态文字的按钮仍使用原控件底色。
- 微信仅使用薄荷蓝，不读取历史主题偏好，也不提供切换入口或 setter；H5 继续使用已有主题偏好和选择器。不得因共用 store 恢复微信主题切换。

### H5 可选主题（微信固定薄荷蓝）

H5 提供薄荷蓝（默认）、青柠、晴空蓝、珊瑚紫、曜夜橙五套主题；微信固定薄荷蓝，旧设备偏好不参与微信首屏渲染。晴空蓝替代活力橙；旧 `orange` 本地偏好自动迁移为 `blue`。

晴空蓝采用白底 `#fffffe`、深蓝标题 `#094067`、灰蓝正文 `#5f6c7b`、蓝色按钮 `#3da9fc` 配白字；辅助蓝 `#90b4ce` 用于较强结构线，粉红 `#ef4565` 用于辅助高亮。补充浅蓝选中底 `#e8f4ff`、细线 `#e0eaf2`、冷灰禁用底 `#dce7ef`。按压反馈采用内侧阴影、表面色变化或位移动效。有背景的按钮保持不透明，不能降低整块按钮的 opacity；内侧阴影复用 `--ui-shadow-control-pressed`，避免悬浮按钮透出页面内容。下方状态色及报名进度语义保持不变。切回其他主题时基础色必须显式恢复，不能残留晴空蓝的正文/线色。

珊瑚紫采用白底 `#ffffff`、深紫标题 `#1f1235`、正文 `#1b1425`、珊瑚按钮 `#ff6e6c` 配深紫字；柔紫辅助 `#67568c`、浅黄图形高亮 `#fbdd74`，补充选中浅底 `#fff0ef`、细线 `#e9e2ef`、禁用底 `#e5dfed`。主题选择使用两列布局。

曜夜橙为深色主题：页面 `#0f0e17`、卡片/弹窗 `#1b1926`、标题 `#fffffe`、正文 `#a7a9be`、橙色按钮 `#ff8906` 配白字；辅助色 `#f25f4c` / `#e53170`。补充深色选中底、结构线、禁用色及状态徽章浅字深底；状态含义保持一致。单色 PNG 图标随主题提亮，头像和队徽保持原图。切换主题必须同时恢复深浅表面、状态色及图标滤镜。

**主色不等于状态色**：状态语义是固定值，不随品牌主题切换（换主题不能把「成功」变成任意颜色）：

| 语义 | Token 对（fg/bg） | 值 | 用途 |
| --- | --- | --- | --- |
| 成功/已报名 | `--ui-color-success-fg/-bg` | `#226342` / `#e8f5ee` | 成功状态徽章、已完成标记 |
| 提醒/待支付/付费 | `--ui-color-warning-fg/-bg` | `#805414` / `#fff3db` | 待办、费用相关提醒 |
| 失败/危险 | `--ui-color-danger-fg/-bg` | `#a13432` / `#fdecea` | 取消、错误、解散等危险区 |
| 中性状态 | `--ui-color-neutral-fg/-bg` | `#526174` / `#f0f2f5` | 无倾向的状态说明 |

- 饱和警示色 `--ui-color-danger`（`#ff5470`）与琥珀 `--ui-color-warning-soft`（`#fde24f`）保留作高亮底/图形色，徽章类状态优先用上表淡底 + 对比前景。
- **报名进度三段色是固定语义**（`--now-progress-pending` 黄 `#fde24f` / `ready` 薄荷 `#00ebc7` / `extra` 海军蓝 `#00214d`），不随主题；低于最低人数黄色、达标段薄荷、超出门槛段海军蓝、剩余容量浅底，保留门槛分隔点。

## 间距、圆角、描边、阴影、点击尺寸

- 基准卡内边距 26rpx / 28rpx；相关信息横向组合，长内容自然换行（`overflow-wrap: anywhere`），不删信息压高度。
- 圆角：基准卡 `--ui-radius-card: 32rpx`、按钮 `--ui-radius-button: 20rpx`；紧凑列表可减少装饰（小圆角、无阴影）。
- 描边：轻线 `--ui-border-default: 2rpx solid var(--ui-color-line)`；`--ui-border-strong` 用 `line-strong`，不再用墨色粗描边。深底组件（hero、时间条）可用自身底色对比，不加描边。
- 阴影：柔和投影族 `--ui-shadow-card/raised/pressed/soft/modal`（色基 `24, 55, 100`），无硬偏移阴影。
- 点击尺寸：主按钮最小高度 88rpx；次要操作保持足够热区但不做满宽大按钮。

## 主题运行时

- 微信 store 固定 `DEFAULT_ACCENT_THEME`（薄荷蓝），平台编译时排除存储读取和切换方法。H5 的五套主题由 `src/config/themePalettes.ts` 定义并沿用切换；状态的含义保持不变。
- 每个本地页面同时绑定 `page-meta` 与根节点 `app-theme-scope` 的 `themePageStyle`，避免 H5 缓存页面间变量残留。
- 脱离页面层级的 root-portal 弹窗必须显式绑定主题变量；仅依赖页面继承不足以覆盖 H5。
- H5 偏好由 `src/utils/themeStorage.ts` 持久化；微信不读取/写入主题偏好。原生 switch 使用 `accentHex`。

## 动效规范（Motion）

统一 duration/easing token（`--ui-motion-*`），组件引用不散落硬编码；禁止 `transition: all`，优先 transform/opacity/颜色过渡。

| Token | 值 | 适用场景 |
| --- | --- | --- |
| `--ui-motion-press-duration` | 100ms | 按钮/可点卡按压（80–120ms；缩放 0.98 或表面色变化，禁用态无反馈） |
| `--ui-motion-switch-duration` | 180ms | 分段筛选/标签切换指示块平移（160–200ms，支持快速反向） |
| `--ui-motion-expand-duration` | 220ms | 展开/收起内容（180–220ms；用于需要展开的内容；首页头像不折叠） |
| `--ui-motion-overlay-duration` | 210ms | 底部弹层/确认弹窗进退（180–240ms，退场保留遮罩防点穿） |
| `--ui-motion-progress-duration` | 220ms | 进度/状态徽章颜色过渡（180–220ms；与已验收报名进度一致） |
| `--ui-motion-ease-out` | `cubic-bezier(0.33, 0, 0.2, 1)` | 两端缓、中段顺滑（默认） |
| `--ui-motion-ease-in-out` | `cubic-bezier(0.4, 0, 0.2, 1)` | 进出场对称过渡 |

约束：轻触立即响应、业务动作不等动画；快速连点转向最新目标；卸载/切队/关弹层清理 timer；不新增常驻定时器、轮播、循环装饰动画，不为长列表全体条目绑动画；H5 尊重 `prefers-reduced-motion`（缩短过渡、减位移），小程序保持短时非循环。首页比赛滑动遵循下方现行交互，不因其他组件改版顺手调整手势参数；用户明确要求时单独迭代。

底部 TabBar 的选中色块共用独立滑块，沿用 switch 时长与缓动。色块为覆盖图标和文字的浅主题色圆角矩形，基准尺寸 100 × 92rpx，圆角引用 button token，窄屏在 tab 两侧至少各留 8rpx；微信端色块铺满整个 tab 格子的宽高，呈横向全圆角长条。切换页面立即执行，目标页显示时从原 tab 位置滑向当前 tab；返回缓存页不重播旧动效。滑块适配中央创建入口显示/隐藏的两种布局，保持图标与文字热区不变。

### 球队会员头像皇冠与年度参与星（2026-10-07）

报名头像的会员皇冠使用金属质感金色皇冠（2026-11-04 替换原 Lucide 线稿皇冠：渐变金属、珍珠顶珠、红宝石与白色外描边，原生 1.8:1 以 aspectFit 显示不拉伸；素材 `src/static/icons/member-crown-gold.*`，生成入口 `scripts/generate-member-crown.mjs`，荣誉海报画布同步使用），保留原有皇冠留白、展开过渡。皇冠静态展示、不旋转，水平居中「戴」在头像正上方并约 40% 高度压住头像上沿（叠放条与展开网格一致）；原摇摆动画已于 2026-11-04 按用户要求取消，身份标识不使用常驻循环动画。仅报名组所属球队的在队付费会员显示皇冠。

展开报名头像名单显示「20级」等紧凑等级，等级为本球队历年累计参与星数 ÷ 100 × 3 后四舍五入取整数（例如累计 655.5 星显示 20 级）；收起时隐藏等级与预留高度。0 星显示 0 级，个人组无球队维度、接口缺累计字段时不显示等级，不使用年度星数冒充累计。年度按北京时间比赛开始年份归属，历史年度分别保留，累计等级和段位不因跨年清零。会员身份与星数独立。使用报名组所属球队的累计值，不能从其他球队名册补齐。

展开名单的前三名按后端年度 participation_rank 显示金银铜色；年度零星没有名次荣誉。点开头像显示完整累计星数与「活跃段位 · 永恒钻石」等段位评价，每位有有效累计星数的队员都能获得称号，包括零星新队员。段位沿用等级换算：0–1 级倔强青铜、2–3 级秩序白银、4–5 级荣耀黄金、6–7 级尊贵铂金、8–9 级永恒钻石、10–11 级至尊星耀、12 级及以上最强王者；不按榜单名次决定段位。个人组或旧接口缺少累计星数字段时，不推断为零星段位。

头像弹层的称号徽章和累计星数随段位使用青铜、白银、黄金、铂金青、钻石蓝、星耀紫、王者金橙色。配色通过 `--ui-avatar-tier-*` token 表达，深色主题用浅色文字配深色底；切回浅色主题显式恢复。保留会员金色细框、正方形 aspectFill 头像和现有圆角。统计页提供「出勤记录」「年度活跃榜」「历史活跃榜」三个分页签：年度榜显示本年度当前球队累计星数，历史榜显示当前球队历年累计星数（含今年），与等级、段位的累计口径一致。榜单按对应口径的后端星数与并列次序排列，不向队员展示权重或计算细节。旧出勤字段继续用于历史出勤明细。

### 活跃榜排版

年度、历史活跃榜都显示队员当前累计段位；年度榜的星数与排名仍按本年度，不能用年度星数评定段位。通过同球队无日期统计结果按 user_id 关联累计星数，缺数据不推断段位。列表使用头像与姓名、段位两行信息，右侧独立显示星数；段位复用头像弹层的 `--ui-avatar-tier-*` 前景/背景 token。前三名的非零星数序号用金银铜色，数字采用等宽数字。

统计分页签由页面本地 wrapper 提供下方 32rpx 间距，避免小程序样式隔离导致父 scoped 样式无法作用到子组件。卡内边距 26rpx，榜单标题 34rpx、说明/列标题 22rpx，标题区与名单间距 24rpx，名单行上下各 22rpx 留白；长姓名允许自然换行。

榜单段位和头像弹层共用 `ActivityTrophyIcon`，奖杯原生轮廓继承段位文字颜色。每行完整点击区域打开同一个 `AvatarPreviewDialog`，显示该队员在本球队的累计星数；弹层位于页面根层，出现至退场完成期间锁定底层滚动。沿用报名页的荣誉分享权限：本人弹层可进入「分享我的荣誉」，其他队员可预览；切页或退出登录时关闭弹层。

榜单和弹层绑定统计加载时的用户、球队快照；身份改变即清空旧数据，迟到响应不得覆盖新上下文。会话初始化中的中间身份变化只清空，由当前加载继续使用最终身份；初始化失败显示错误，不自动反复重试。页面可见时主动切队重新加载，隐藏页在下次进入时加载。

## 颜色例外

- 球衣颜色、球队颜色等业务数据值不是视觉 token，不能因颜色扫描而删除。
- 首页球体、球网、图片遮罩等插画内部颜色属 decorative asset colors，可保留在组件样式中并在相邻注释标明。

## 页面主题作用域与个人中心

所有本地页面的最外层 view 同时绑定 `app-theme-scope` 和响应式 `themePageStyle`；`page-meta` 继续用于原生页面及滚动锁。H5 的 page-meta 实现通过 document.querySelector 命中首个缓存页，不能作为唯一主题载体。语义 token 必须在 `.app-theme-scope` 上重新计算，避免继承到其他页面已解析的旧配色。外部 web-view 文档独立管理主题。

微信个人中心沿用报名页的浅底、独立圆角卡片与柔和阴影（H5 保留原样式）：资料卡只突出编辑，统计为单张中性卡，球队列表合并当前身份标记并保留独立切换入口，比赛按行展示，钱包不使用大块警告底色。消息/联系/设置合并为服务列表；微信移除主题入口，H5 主题选项折叠展示；低频退出与清理操作放底部；调试身份入口折叠，正在代用身份时始终露出恢复入口。业务能力和权限保持不变。

### 大厅发起入口权限（微信）

发起权限按身份递进：所有登录用户可发散人约球；当前球队的队长、领队还可发自己球队的比赛。大厅无比赛时，普通用户只看到「发起散人约球」，队长/领队并列「发起球队比赛」主按钮和「发起散人约球」描边按钮。筛选或搜索无结果时，队长/领队的次要入口「发起比赛」打开类型面板。球队身份以当前球队为准，与创建页校验一致；能管理其他球队但当前球队不可管理时，按普通用户处理。场馆账号并列「发起场馆组局」和「发起散人约球」；同时是队长或领队时入口过多，改用「发起比赛」打开类型面板。

### 场馆组局详情（微信）

详情页 hero 不显示主客队对阵，下方用「对阵两边」卡片展示每边状态：球队边显示队名，有散人的边显示「散人组」，空边显示「虚位以待」。散人不选边、界面不出现甲乙概念。「带队报名」只对当前球队的队长、领队显示；退出、移出使用浅危险色并二次确认。发布表单复用散人约球页（`?mode=venue`），不设报名上限和支付方式，发布后不能改人制。

## 复用与表单收口

微信普通操作优先复用 `AppButton`，默认/`dark` 与 `lime` 主按钮统一消费 `--ui-button-bg/fg`，保持薄荷蓝；`secondary`、`outline`、`danger` 与禁用状态保留语义。需要原生 `open-type` 或已有原生节点的按钮，在节点所属组件的 scoped 样式导入 `button-controls.css`，使用 `ui-native-button` 让图文整体水平、垂直居中，主操作再加 `ui-native-button--primary`。共享 `ui-subtle-control` 同样使用居中规则，尺寸与圆角仍由已有 token 和组件负责。不得通过父级 scoped 样式穿透子组件，也不得将包含多列内容的列表整行/卡片强制套用按钮居中规则；H5 不应用这些覆盖。

- 微信比赛详情 hero 的地点为单一入口：定位图标、地址、球场插画（`HOME_VISUAL_ASSETS.venueMap`）与灰色单 chevron 同属一行，整行打开地图，不另设「导航」按钮。插画与文字并排，长地址换行不压图；没有经纬度时不显示插画和 chevron，插画加载失败时只隐藏插画。
- 发布表单的场地选择统一使用 `VenueEntryField` 入口和 `VenuePickerSheet` 底部弹层（常用场地、手动输入、地图选点），流程由 `useVenuePicker` 提供；两者位于主包，供 `matches` 与 `challenges` 分包共用。微信散人约球的常用场地合并本地历史和后端建议，H5 保留原字段。
- 确认/报名状态选择使用 `ConfirmDialog`，通过按钮文字、图标、tone 和事件区分业务，不能另写弹窗蒙层与动画。
- 球队创建与管理的队徽区域共用 `TeamLogoField`；组件只负责预览和操作入口，上传与保存由页面负责。
- 可编辑输入框使用主题 surface 与轻边框；灰色中性底仅用于状态、占位头像等非输入场景。
- 微信端 `MatchScheduleFields`（创建比赛、散人约球共用）的薄荷色只表达选中：日期卡未选中、「更多日期」和时间磁贴使用 surface 与 `--ui-input-border`，选中日期使用实色 `--ui-color-accent` 底和 `--ui-color-accent-fg` 文字。选中近 7 日以外的日期时，「更多日期」按钮以同样的选中样式显示该日期；回填或日历选择的靠后日期自动滚入视野，点按日期卡不移动列表。
- 加载态共用 `RunningLoader`，不再维护人物精灵图；图形及文字使用主题变量。

头像列表统一使用 `ExpandableAvatarStack`；头像类型定义位于 `components/ui/avatarTypes.ts`。旧 `AvatarStack` 与 `DateRail` 已无运行时入口并移除。

### 比赛编辑入口

比赛详情的「修改比赛」进入对应的原发布表单，使用 `editId` 回填现有数据并更新同一场比赛，不使用缩减字段的编辑弹窗。散人约球可编辑标题、人制、报名上限、时间、场地、费用方式与金额、支付方式和说明；地图返回不重新回填。保存失败保留输入，载入失败禁止提交。球队比赛同样复用发布表单，类型转换遵循后端既有的接约状态限制。

### 悬浮 TabBar

底栏采用两侧各留 24rpx、底部安全区上方 12rpx 的悬浮条，高度 116rpx；微信端两侧收窄为 12rpx，与底部留白一致，高度降为 100rpx；底部距离用 `--ui-tabbar-bottom-offset`（安全区减 14px、最少 12rpx），iPhone 只避开 Home 横条而不叠加整段安全区，`--ui-tabbar-clearance` 随之计算。微信四个 Tab 统一使用确认稿的 32rpx 圆角、92% 白色表面、细线房屋/足球/统计/人物图标，当前页图文薄荷色、其他页灰色、选中滑块为 `--ui-tabbar-selected-bg`（墨色 8% 淡叠加，须明显深于玻璃底栏）；中央薄荷按钮为白色加号，消费 `--ui-tabbar-active/radius`。保留切换、审核过滤、未读角标及创建菜单。四个 Tab 页统一使用 `--ui-tabbar-clearance` 留出底部空间；原其他平台底栏分支保留。

顶部导航与 TabBar 共用 `--ui-glass-*` 模糊材质：顶部不显示分割线；显式 plain 头部仍保持透明。微信选中态由薄荷细线图标与文字加中性灰色块共同表达，弱于中央主按钮。主题色 PNG 图标不使用 CSS mask；真机效果需验收。

### 底部固定悬浮操作面板

选中球队的确认区复用 `StickyActionBar flat reserve-space`，整块卡片（标题、说明、可选密码和按钮）固定在视口底部。`reserveSpace` 默认关闭；开启时以组件自身原生节点实际高度生成滚动占位，结合底部安全区、`--ui-action-bar-bottom` 和 `--ui-card-gap`，内容/窗口变化后重新测量。业务内容由原有组件负责，布局不依赖跨组件 scoped 穿透；H5 加入页保留页面内布局。微信确认面板通过 `enter-from-bottom` 开启首次上滑淡入，复用 overlay 时长和 ease-out token，始终保留横向居中 transform；同一面板切换内容不重播。通过 `leave-to-bottom` 开启下滑淡出，复用 `useOverlayPresence` 延迟卸载、overlay 时长与 ease-in-out token；退场保留展示快照及占位，禁用输入和确认操作。加入成功时父级保留确认组件直至动画结束，快速重新选队取消旧的移除回调；减少动态效果设置下立即收起。

## 加入球队目录

微信加入页默认展示全部可加入球队，按固定 50 条 offset 分页读取后在本页缓存，输入即时筛选、清空恢复；加载和筛选均不改变密码/资料 gate 语义。创建入口位于搜索框下方，复用 AppButton 的 `secondary` 变体（`--ui-button-secondary-bg/fg`），海军蓝白字区别于薄荷搜索按钮。审核态仍按 `canShowCreateEntry` 隐藏，slot 容器通过列布局拉伸组件宿主。加入成功页在返回、下拉刷新与下一步导航前刷新成员关系，确认已退队则清理成功状态、密码和筛选并恢复完整目录；网络失败与临时空会话不能视为已退队，迟到结果不得影响其他账号或较新的成功记录。H5 保留手动搜索及原入口。

## 球队管理

微信创建球队页复用首页的夜场照片、建队盾牌和加入球队球衣插画，使用复用的深色引导页头、独立圆角表单卡与次要加入入口，输入框保留轻描边。素材沿用 MinIO 缓存，不新增大图。密码输入框与提交按钮间距由 `TeamCreatePanel` 内部的原生 view 提供 `var(--ui-space-8)`（32rpx）顶部 padding，不能通过父级 scoped/deep 样式跨组件修改 `AppButton`。

球队资料、队员管理和队员出勤使用页面内 `TeamManagePanel` 统一圆角卡面、标题与 token 内边距；布局由本地 wrapper 承担，不依赖父级 scoped 穿透组件。资料、入队密码与低频解散操作分组；队员按管理角色、普通队员、冻结队员分组，保留姓名和角色；出勤、编辑、冻结／恢复、移除合并为同一排带图标的紧凑胶囊按钮，尺寸及浅底风格统一，移除保留浅危险语义色。比赛出勤展开后使用 success/warning/neutral 的前景和背景对展示统计及状态，姓名、比赛名和地点允许换行。保持原有权限、提交与确认流程。
