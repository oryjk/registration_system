# 当前版本产品说明书

更新时间：2026-05-13

> 注：本文档为 Rust 老后端时期的产品快照。旧 Rust 后端代码目录 `registration_system_rs/` 已于 2026-08-30 从工作区删除（git 历史可查）；当前技术实现以 `registration_system_go/` 为准。

## 1. 产品定位

本产品是一个面向业余足球队的赛事报名、约队、球队管理、出勤统计和账单结算系统。当前工作区包含：

- 微信小程序端：面向球员、队员、队长、领队和普通用户。
- 管理后台：面向运营、管理员和超级管理员。
- Rust 后端：提供小程序端与管理端 API、鉴权、持久化和第三方服务接入。

当前版本重点服务一个球队试运行场景，但代码已经具备多球队、多管理员、约队、支付、通知和系统配置能力。

## 2. 用户角色

| 角色 | 当前能力 |
| --- | --- |
| 普通用户 | 微信登录、完善资料、查看比赛、个人报名、查看账单、查看通知、参与散人约队 |
| 球队成员 | 查看球队、查看统计、参与球队比赛、签到、查看出勤记录 |
| 队长/领队/副队长 | 创建/编辑未开始比赛、管理队员、代球队报名、配置签到、赛后互评、发起结算 |
| 管理员 | 登录管理后台、管理被分配球队、活动、球员、账单和约队 |
| 超级管理员 | 管理所有后台资源、管理员账号、系统地图配置、管理员和球队绑定 |

## 3. 小程序端功能

### 3.1 首页

完成状态：已完成

当前能力：

- 展示最近比赛卡片。
- 展示约队推荐。
- 展示用户与球队相关摘要。
- 显示报名进度和参与头像。
- 支持从首页进入比赛详情、全部比赛和约队详情。
- 首页展示数量由后端小程序运行配置控制。

待讨论：

- 首页信息优先级是否固定为“比赛优先”，还是按临近时间统一混排比赛和约队。
- 是否需要增加公告、队费提醒、未读待办等运营位。

### 3.2 比赛列表与比赛详情

完成状态：大部分完成

当前能力：

- 查看比赛列表和比赛详情。
- 比赛支持个人报名：参加、请假、迟到、未报名。
- 支持球队报名和取消球队报名。
- 发布者是当前用户所在球队时，避免展示会造成循环的球队报名入口。
- 比赛卡片支持左右对阵展示。
- 支持双方球服颜色展示，当前小程序已改成球服样式。
- 支持外战/内战标识。
- 地址支持经纬度，后端提供位置搜索和坐标反查。
- 未开始的比赛，队长/领队可编辑时间、地点、对手、球服颜色等信息。
- 支持签到入口和签到配置。
- 支持赛后球队互评。
- 支持比赛费用结算入口，队长/领队可以操作。

已知未完成或待补齐：

- 管理后台活动 service 对新增字段 `match_kind`、`source_activity_id`、`team_registration_count` 的类型同步不完整。
- 管理后台活动列表拆分计划只完成了一部分，`ActivityListTable.vue` 尚未落地。
- 地图打开和选点体验需要继续实机验证，尤其是微信小程序地图能力和后端地图供应商配置之间的边界。

待产品讨论：

- 比赛状态流转规则：报名中、进行中、已结束、已取消是否完全人工操作，还是需要定时自动推进。
- 内战比赛是否需要双方队名，还是只展示同队分组。
- 球衣颜色是否需要固定色板、历史常用色、或自定义颜色。
- 队长编辑比赛的截止时间：开赛前任意修改，还是开赛前 N 小时锁定。

### 3.3 创建比赛

完成状态：已完成

当前能力：

- 创建比赛，填写时间、地点、对手、人数制、主客队球服颜色。
- 选择内战或对外比赛。
- 设置签到配置。
- 创建后接入真实后端 `/api/activity`。

待产品讨论：

- 创建比赛时是否必须选择主队。
- 是否需要费用规则在创建比赛时配置，还是赛后结算时再配置。
- 是否需要支持封面图。

### 3.4 约队大厅

完成状态：大部分完成

当前能力：

- 查看约队列表。
- 支持球队约队和散人约队两种类型。
- 球队约队：发布球队已占一侧名额，等待另一支队伍接约。
- 散人约队：按人数制需要凑齐双方总人数，例如 8 人制需要 16 人。
- 约队卡片区分球队约队和散人约队。
- 散人约队显示报名进度和头像，不显示对阵进度。
- 支持接约和取消约队。

已知未完成或待补齐：

- 当前不支持“一个队接部分人数，再由散人补齐”的混合模式，这是明确暂不支持的范围。
- 散人约队完成后如何分队、如何生成正式比赛，还需要进一步产品化。

待产品讨论：

- 散人约队满员后的分队规则。
- 约队费用是否按人预估，是否需要押金。
- 约队被接后是否自动生成比赛，还是需要发布者确认。

### 3.5 球队管理

完成状态：大部分完成

当前能力：

- 创建球队、搜索球队、加入球队。
- 查看球队资料、队员列表、队员头像。
- 队长、领队、副队长等角色队员单独展示在普通队员上方。
- 冻结队员单独分组展示在普通队员下方。
- 队长/领队可添加队员、编辑角色和球衣号、冻结/恢复、移除队员。
- 点击队员可查看所有出场记录，包括参加、请假、未报名。
- 出场记录按年份分组，年份行显示总场次、参加场次、请假场次，并支持折叠。

已知未完成或待补齐：

- 多球队切换和角色边界需要继续实机验证。
- 冻结队员对未来报名、统计、结算的影响规则需要产品确认。

待产品讨论：

- 角色体系是否固定为队长、领队、副队长、队员。
- 冻结状态是否有原因、开始/结束日期和自动恢复。
- 队员是否可以主动申请加入，队长审批。

### 3.6 统计页

完成状态：大部分完成

当前能力：

- 展示当前用户个人出勤记录。
- 个人出勤记录按年份分组。
- 展示当前球队今年以来的出勤排名。
- 统计包含头像。
- 已统一统计口径：未完成比赛不参与场次统计。

待产品讨论：

- 统计维度是否只看今年，还是支持自定义周期。
- 请假、迟到、未报名在排行中的权重如何计算。
- 冻结期间是否计入未报名。

### 3.7 我的页面

完成状态：已完成

当前能力：

- 展示个人资料、头像、球队上下文。
- 展示我的比赛入口。
- 展示钱包、账单、订单相关入口。
- 支持会员续费/球队会员支付流程。
- 支持通知红点。

待产品讨论：

- 我的页面是否需要更多账户安全、手机号解绑、隐私设置。

### 3.8 账单与结算

完成状态：后端和小程序基础能力完成，业务规则仍需继续产品化

当前能力：

- 查看个人余额。
- 查看个人账单流水。
- 创建充值订单。
- 查看支付订单、同步订单状态、取消未支付订单。
- 创建球队会员订单。
- 比赛费用结算支持：
  - AA 模式。
  - 手动指定不同人员费用。
  - 只针对报名参加人员。
  - 自定义人员范围。
- 结算后生成账单并扣减用户余额。
- 队长/领队和后台管理员可发起结算。

已知未完成或待补齐：

- 前端没有覆盖全部账单管理体验，例如历史订单详情、退款、撤销结算、异常账单处理。
- 账单表历史逻辑本身仍不完整，之前已明确“账单表不是重点，可以后续重写”。

待产品讨论：

- 比赛结算是否允许重复结算、撤销、补扣。
- 非报名人员参与结算的业务场景和权限。
- 余额不足时如何处理：允许负数、阻止扣费、或生成待支付订单。
- 队费、会员费、罚款、比赛费用是否统一成订单中心。

## 6. 已确认的产品/技术决策

1. 球队 ID 已切换为数据库自增数字 ID，后端使用 `i64`，小程序和管理端使用 `number`。
2. 活动 ID 和约队 ID 继续保持字符串主键，当前只对球队域完成数字化迁移。

## 7. 当前版本可作为产品需求继续讨论的主题

1. 多球队模型：当前开发库阶段可以只有一支球队，但产品是否支持多球队、多队长、多管理员。
2. 约队模型：球队约队、散人约队、混合约队是否都支持，以及满员后如何生成比赛。
3. 结算模型：AA、手动、报名人员、自定义人员、余额不足、撤销、补扣和审计。
4. 统计口径：完成比赛、未完成比赛、冻结队员、迟到、请假、未报名的口径。
5. 图片存储：头像、球队 Logo、比赛封面是否全部强制 MinIO，并是否接 CDN。
6. 权限模型：队长/领队/副队长/管理员/超级管理员之间的权限边界。
7. 活动生命周期：报名中、进行中、结束、取消是否自动流转。
8. 通知体系：站内通知、微信订阅消息、财务提醒、比赛提醒。
9. 管理后台产品化程度：是否发展成完整运营后台和财务后台。
