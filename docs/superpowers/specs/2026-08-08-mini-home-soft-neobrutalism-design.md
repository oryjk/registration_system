# 小程序首页 Soft Neo-Brutalism 视觉改造设计

## 目标

将小程序首页调整为参考图所示的轻量新粗野主义风格，形成清晰的赛事信息层级，同时保持现有首页数据、接口、状态、导航和交互行为不变。

## 范围

本次只修改以下首页视觉文件：

- `registration_system_mini/src/pages/home/index.vue`
- `registration_system_mini/src/pages/home/components/HomeHeroSection.vue`
- `registration_system_mini/src/pages/home/components/HomeMatchList.vue`
- `registration_system_mini/src/pages/home/components/HomeOpportunityList.vue`
- `registration_system_mini/src/pages/home/components/HomeSkeleton.vue`

不修改共享的 `AppTabHeader.vue`、`BottomTabBar.vue`，避免其他页面随试验一起变化。不修改 API、Mock、store、view model、路由、事件、展示文案或业务计算。

`HomeMatchList.vue` 同时被“全部比赛”页面复用，因此为它新增可选的纯视觉 `variant` 属性，默认值保持现有风格；首页明确传入 `brutalist`，所有其他调用方无需修改且继续使用默认样式。该属性只控制根节点 class，不改变 props 数据或 emits。

## 视觉语言

- 页面背景：暖白 `#f4f0e8`，取消当前绿色径向渐变。
- 主文字和结构线：近黑 `#111310`。
- 表面：白色 `#fffdf8`。
- 主强调色：荧光绿 `#b9f24b`；辅助绿色使用 `#dff8a8`。
- 危险/超额色：`#ff6b5f`。
- 描边：主要卡片使用 `3rpx solid #111310`，次级控件使用 `2rpx solid #111310`。
- 圆角：卡片控制在 `4rpx` 至 `8rpx`；头像和进度条端点可继续使用圆形。
- 阴影：使用无模糊硬阴影，例如 `8rpx 8rpx 0 #111310`，不用柔和扩散阴影。
- 字体：继续使用系统中文字体；标题 `800-900`，正文 `500-700`，letter-spacing 保持 `0`。

## 首页结构

### 页面与标题区

保留共享顶部栏。首页内容背景改为暖白，区块间距保持移动端紧凑节奏。区块标题采用粗黑标题；区块链接统一使用 `2rpx` 黑框、白底、`4rpx` 圆角的矩形按钮；“热”标记改为方形荧光色贴纸。

### Hero

保留现有轮播、点击行为、动态图片和无图足球装饰。Hero 改为低圆角深色面板，增加黑色描边与硬阴影；遮罩固定为从左侧 `78%` 黑色透明度过渡到右侧 `30%`。标题保持当前文案，CTA 改为荧光绿矩形贴纸按钮，并带黑色描边。无图时保留球门和足球视觉，但去除柔和光晕。按压时整体向右下平移 `4rpx` 并移除同等距离的硬阴影，松开后恢复。

### 最近比赛卡片

保留日期栏、比赛信息、报名进度、头像、状态和操作按钮。卡片改为白底黑框硬阴影；日期栏使用近黑底和直角结构，时间块使用荧光绿底黑框。标签改为低圆角描边贴纸。报名进度继续使用现有双区段算法：绿色表示目标人数内报名，红色表示超额人数，黑色分界线表示目标人数。操作按钮改为近黑矩形按钮。

### 约队机会卡片

沿用比赛卡片视觉体系，日期栏、标签、报名进度和按钮使用同一套边框、圆角和颜色规则。不同状态继续通过现有 class 区分，但使用描边和有限的浅色底，不使用柔和胶囊。卡片按压反馈与 Hero 一致：向右下平移并同步缩短硬阴影。

### 加载与空状态

骨架屏使用暖白/浅灰块、黑色细描边和低圆角，保留现有 shimmer。空状态固定为白底、`2rpx` 黑框、`4rpx` 圆角且无阴影，保持次要层级。

## Wot UI 边界

本次不为了视觉试验强行替换业务卡片。首页双区段进度条无法由单个 `wd-progress` 精确表达，继续保留自定义实现。后续标准按钮、表单和单段进度场景再逐项迁移到 Wot UI。本次样式命名和组件边界保持现状。

## 响应式与跨端

- 使用 `rpx`，不引入 DOM API、Web-only CSS 逻辑或新的运行时依赖。
- 所有固定格式元素维持稳定尺寸，长标题允许换行，日期栏不被正文挤压。
- H5 验证 `390x844` 移动视口与 `1280x900` 宽屏视口；宽屏只验证内容不溢出或失控拉伸，主要设计基准仍是移动端。
- 执行 `bun run type-check`、`bun run build:h5` 和 `bun run build:mp-weixin`。
- 浏览器检查首页首屏、滚动后的约队区块和控制台错误，并执行以下不提交数据的回归路径：点击 Hero 跳转约队大厅后返回；点击第一张比赛卡片进入详情后返回；点击第一张约队卡片的非按钮区域进入详情后返回；点击“全部比赛”进入列表并确认 `HomeMatchList` 仍为默认视觉后返回。不得点击“去报名”“去接约”“取消报名”等可能提交数据的主操作按钮。
- 当前没有已连接的微信开发者工具自动化会话，本轮微信端只验证构建。微信真机/开发者工具中的黑框、硬阴影、长标题、超额进度和底部栏遮挡作为明确的后续人工视觉检查项，不把 H5 截图等同于微信视觉结果。

## 成功标准

- 用户能够明显识别参考图的暖白、黑框、硬阴影、低圆角和粗体层级。
- 首页所有现有内容、Mock 数据和点击行为保持不变。
- 没有文字溢出、控件遮挡、卡片错位或底部栏覆盖内容。
- H5 与微信小程序均能构建。
- 最终差异只允许包含上述 5 个首页文件、`HomeMatchList` 的视觉 `variant` 接口以及本设计/计划文档；`src/api`、`src/mock`、store、路由、共享顶部栏和底部栏不得因本任务产生新差异。
- 首页不传业务参数的新变体只改变 class；“全部比赛”页面仍使用默认风格，视觉和行为保持原样。
- 实施前将 `git status --short` 保存为 `/tmp/registration-system-wot-home-baseline-status.txt`，并将上述 5 个首页文件的差异保存为 `/tmp/registration-system-wot-home-baseline.diff`。完成后以这两个基线文件核对新增差异，不能把工作区原有修改算作本任务结果。
