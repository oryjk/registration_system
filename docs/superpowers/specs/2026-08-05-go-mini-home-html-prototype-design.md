# Go 小程序首页 HTML 原型设计

## 目标

在正式修改 `registration_system_mini_go/` 前，先交付一个可直接在浏览器打开的高保真首页原型，用于确认信息层级、视觉样式、移动端布局和操作语义。

首页定位为“赛事任务台”：用户打开页面后，应先看见最需要处理的比赛，再快速回顾最近结束的比赛。原型只验证首页，不实现比赛详情、更多比赛、约队大厅或其他页面。

## 交付物

- 文件：`docs/prototypes/go-mini-home.html`
- 形式：单个 HTML 文件，内含 CSS、内联 SVG 图标和少量原生 JavaScript
- 运行：无需安装依赖或启动服务，浏览器直接打开
- 目标视口：360px、390px、420px 手机宽度；桌面端居中展示最大宽度 420px 的手机画布
- 图片：复用 `registration_system_mini_go/src/static/football-field.jpg`，不加载远程图片或字体

## 页面信息架构

页面从上到下包含以下区域：

1. **预览状态栏**：固定显示时间 `22:17`、信号、`4G` 和电量 `83`，仅用于 HTML 视觉预览；正式小程序使用平台状态栏和安全区。
2. **顶部栏**：页面标题 `首页`、位置 `成都 · 高新区`、更多与定位图标按钮。
3. **紧凑品牌横幅**：显示 `约球开踢`、`组队 · 报名 · 上场` 和 `进入约队大厅`。横幅使用足球场图片与深绿遮罩，不超过首屏高度的约 18%。
4. **最近要处理的比赛**：区块标题配数量提示 `3 场待处理` 和 `全部比赛` 入口。
   - 第一场使用完整重点卡片，集中展示日期、截止时间、比赛信息、报名进度、个人状态和主操作。
   - 其余最多两场使用紧凑待办行，只展示日期、比赛名、待处理事项和主操作。
5. **已结束的比赛**：首页最多展示六条紧凑列表，每条只展示日期、比赛名和地点；区块右上角提供 `查看更多` 入口。
6. **底部导航**：首页、约队、中间创建按钮、统计、我的五个入口；首页为默认激活态。

原截图中的“约队机会”大块空状态不再单独占据首页。约队入口合并到紧凑横幅和底部导航，避免与赛事待办争夺注意力。

## 视觉系统

### 颜色

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| 深绿主色 | `#13251A` | 横幅、重点按钮、激活导航 |
| 荧光绿强调 | `#B8F229` | 关键进度、重点日期、创建按钮 |
| 页面底色 | `#F3F5F1` | 页面画布 |
| 内容表面 | `#FFFFFF` | 卡片与列表表面 |
| 主文字 | `#172019` | 标题与正文 |
| 次文字 | `#667068` | 地点、说明和辅助信息 |
| 边框 | `#DDE3DC` | 卡片与列表分隔 |
| 危险/异常 | `#C53B34` | 已截止或异常状态，并同时显示文字说明 |

荧光绿只用于关键强调，不作为大面积背景，也不直接作为白底文字。作为文字或图标时只能出现在深绿表面；作为进度、日期或按钮背景时必须搭配 `#13251A` 深色前景。功能状态不能只依赖颜色表达。

### 形态与排版

- 卡片圆角为 10-12px，使用细边框和轻阴影；不使用嵌套卡片。
- 状态标签可使用胶囊形态，但普通按钮保持稳定的圆角矩形。
- 中文使用本地系统黑体栈，不请求远程字体；日期、人数和时间启用等宽数字。
- 页面标题 24px，区块标题 20px，卡片标题 17-18px，正文 14-16px，辅助文字不小于 12px。
- 使用 4/8px 间距体系；正文左右边距在手机端为 16px。
- 横幅使用现有足球场图片与稳定宽高比，图片使用 `object-fit: cover` 和约 65% 的水平焦点，避免加载导致布局跳动。图片加载失败时保留 `#13251A` 纯色背景与深色遮罩，横幅文字和按钮仍须达到 WCAG AA。

### 交互与动效

- 所有可点击区域至少 44x44px，相邻点击目标至少间隔 8px。
- 按压反馈使用 150-200ms 的颜色、透明度或轻微缩放变化，不改变布局尺寸。
- 尊重 `prefers-reduced-motion`，关闭非必要过渡。
- 纯图标按钮使用内联 Lucide 风格 SVG，并提供 `aria-label`。
- 所有按钮使用语义化 `button`，键盘焦点必须清晰可见；本地提示通过 `aria-live="polite"` 同步给辅助技术。

## 原型交互边界

所有未实现入口统一采用“不导航、不改变页面状态、显示轻量提示”的行为：

| 控件 | 提示文案 | 状态变化 |
| --- | --- | --- |
| 顶部更多 | `更多功能将在后续实现` | 无 |
| 顶部定位 | `位置选择将在后续实现` | 无 |
| 进入约队大厅、底部约队 | `约队大厅将在后续实现` | 无 |
| 去报名、查看详情、全部比赛 | `比赛详情将在后续实现` | 无 |
| 查看更多 | `更多比赛页面将在后续实现` | 无 |
| 底部统计 | `统计页面将在后续实现` | 无 |
| 底部我的 | `个人中心将在后续实现` | 无 |
| 中间创建 | `创建比赛将在后续实现` | 无 |

- 首页导航始终保持激活，不演示与当前内容不一致的导航切换。
- 提示在页面底部导航上方显示约 2 秒，通过 `aria-live="polite"` 宣告；提示出现和消失不得推动正文或遮挡底部导航。
- 不切换报名状态，不伪造任何业务成功。
- 原型不得发起网络请求，不读取或写入本地存储。
- 页面不包含加载中、登录失效或接口错误模拟，因为本阶段没有数据请求。唯一资源失败场景是足球场图片断图，其纯色兜底按视觉系统执行。

## 接口与项目边界

- 本阶段不修改 `registration_system_mini_go/src/`，不调用 Go API，也不定义正式 DTO。
- 管理端 `/api/admin/**` 与小程序用户端 `/api/**` 是完全隔离的两套 HTTP 契约。
- 后续正式实现不得从 `registration_system_backend_fe_go/src/api/` 复用请求函数、DTO 或管理端路由。
- 小程序只能使用 `registration_system_mini_go/src/api/` 和 `src/types/` 中面向用户端的契约；比赛接口必须等待 `registration_system_go/` 中对应用户端 handler 和 DTO 落地后再接入。
- 后端可以在 domain/application 层复用业务能力，但不得让小程序直接依赖 admin handler、admin DTO 或 admin 权限语义。

## 响应式与安全区

- 360px、390px 和 420px 宽度下正文自然纵向滚动，不出现页面级横向滚动。
- 文字优先换行；固定日期块、按钮、图标和导航项不能因内容变化导致布局跳动。
- 桌面宽度下使用中性灰背景，将手机画布居中并限制为 420px。
- 底部导航固定在手机画布底部，正文预留导航高度与 `env(safe-area-inset-bottom)`，最后一条比赛不得被遮挡。

## 验收标准

- 页面六个区域、`3 场待处理`、重点待办、两条次要待办和六条已结束比赛均完整呈现。
- 在 360x800 视口扣除固定底部导航后的初始可视区域内，必须完整看到横幅，并看到重点待办的日期、比赛名、截止时间、报名进度、个人状态和 `去报名` 主操作；不要求看到两条次要待办。
- 在 360x800、390x844、420x900 和 1440x1000 视口下，无横向溢出、文字遮挡、空白图标或底部导航覆盖正文。
- 所有点击目标不小于 44x44px，纯图标按钮具有可访问名称，正文对比度达到 WCAG AA。
- 所有入口按交互映射显示提示，首页导航保持激活，页面无业务状态变化。
- 页面无远程资源、无网络请求、无持久化写入，浏览器控制台无错误；模拟足球场图片加载失败时，横幅文字和按钮仍清晰可读且布局不变。
- 静态原型经用户视觉确认后，再为正式 uni-app 首页和小程序专用比赛接口分别编写实现计划。
