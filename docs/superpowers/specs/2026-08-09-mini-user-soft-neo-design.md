# 小程序“我的”页 Soft Neo-Brutalism 改造设计

## 背景

小程序首页和比赛详情页已经采用 Soft Neo-Brutalism 视觉语言，“我的”页仍保留大圆角、柔光阴影、背景图和渐变遮罩，与其他核心页面不一致。本次改造统一“我的”页视觉，并拆分过大的 `MineHeroProfile.vue`，为后续其他个人与球队页面复用建立稳定组件边界。

本次只改造 `registration_system_mini/` 中的“我的”页及其页面专属组件。现有接口、DTO、Store、登录、支付、权限、路由和数据加载逻辑保持不变。

## 目标

- 将完整“我的”页统一为已认可的 Soft Neo-Brutalism 风格。
- 以“个人档案、球队和比赛”为信息主线，账户功能作为后续服务区。
- 覆盖个人资料、登录退出、球队和身份切换、球队管理、年度统计、我的比赛、钱包账单、消息、信用和会员续费。
- 将 861 行的 `MineHeroProfile.vue` 按稳定职责拆分，页面继续承担业务编排。
- 同时支持 H5 和微信小程序，保持加载、空数据、错误、切换中和支付中状态完整。

## 非目标

- 不新增或修改后端接口、字段和业务规则。
- 不修改其他页面的路由和业务流程。
- 不重构全局认证、球队上下文、通知、支付或 Mock 基础设施。
- 不在本次任务中处理仓库现有的全量测试路径问题和微信构建循环依赖警告。

## 设计方向

采用“个人战绩档案式”信息架构。页面优先回答三个问题：用户是谁、当前代表哪个球队或身份、最近参与哪些比赛。钱包、消息、信用与会员续费仍完整保留，但不抢占比赛主线。

页面顺序固定为：

1. 个人档案 Hero
2. 球队与身份上下文
3. 2×2 年度统计
4. 我的比赛
5. 钱包与账单
6. 消息、信用与会员续费
7. 底部安全区和现有 Tab Bar

## 页面架构

`src/pages/user/index.vue` 继续作为页面编排层，负责：

- 生命周期和首次加载
- 接口并发加载与错误捕获
- 登录、退出和会话刷新
- 球队与身份切换
- 页面导航
- 会员续费和支付流程
- 将后端数据转换成现有展示字段

页面专属子组件只接收 `props` 并通过 `emits` 发出用户意图，不直接调用业务 API，不读取或修改 Store。

## 组件边界

### `MineProfileHero`

负责登录和未登录两种个人档案视觉。登录态展示头像、昵称、所选球队的加入天数、编辑资料和退出入口；球队名称与角色信息统一放在下方球队与身份组件，不在 Hero 重复。加入天数来自所选球队详情中的当前用户成员记录，切换球队后同步更新；未登录态展示登录行动按钮和简短权益预告。

依赖：用户、显示名称和角色标签。真实头像加载失败时使用本地默认头像图标，不使用姓名首字占位。

事件：`editProfile`、`login`、`logout`。

### `MineTeamIdentityPanel`

负责当前球队、球队切换、身份切换和球队管理入口。存在多个球队或身份时支持横向滚动；数量较少时沿用紧凑分段式视觉。管理入口只为 `canManageTeam` 的球队显示。

依赖：当前球队、球队列表、当前身份、身份列表、切换中状态。

事件：`switchTeam`、`switchIdentity`、`manageTeam`。

### `MineStatsGrid`

接收统计项数组并渲染稳定的 2×2 数据板。当前四项为年度比赛数、加入球队数、年度运动时长、加入当前球队天数。组件不计算业务数据。

### `MineMatchSection`

保留最近两场比赛、全部比赛和比赛详情入口。视觉与首页比赛卡一致，但不引入首页业务状态。空列表时显示稳定高度的空状态。

事件：`openAll`、`openMatch`。

### `MineWalletSection`

展示钱包余额和账单入口。继续受 `shouldHideCreationEntrances` 控制，不展示被审核状态隐藏的入口。

事件：`openBilling`。

### `MineServiceGrid`

展示消息、球队信用和会员续费。续费入口只在当前球队具备管理权限时出现；支付中禁用重复操作。

事件：`openNotifications`、`renewMembership`。

### `MineSkeleton`

骨架结构与新页面首屏一致，固定 Hero、上下文和 2×2 统计区域尺寸，减少首次加载布局跳动。

## 通用视觉组件

继续复用 `src/components/neo/` 中现有的：

- `NeoSurface`
- `NeoButton`
- `NeoTag`
- `NeoSectionHeader`
- `NeoSegmentedControl`

页面和页面专属组件不直接散落 `wd-button` 或 `wd-tag`。确需 Wot UI 能力时，通过 `NeoButton`、`NeoTag` 或其他已有 Neo 包装层接入，以保证视觉主题、交互状态和跨端行为统一。

## 视觉规范

- 页面背景使用浅灰绿色纯色，移除当前背景图和大面积渐变遮罩。
- 个人档案 Hero 使用深色底、硬边框和实体偏移阴影。
- 荧光绿用于当前球队、当前身份和主要行动；黄色用于钱包；蓝色和珊瑚红用于辅助统计区分。
- 卡片使用 `2rpx` 至 `3rpx` 深色边框、`6rpx` 至 `10rpx` 实体偏移阴影、`12rpx` 至 `16rpx` 小圆角。
- 标题和关键数字使用高字重，说明文字保持紧凑，不使用负字间距，不按视口宽度缩放字号。
- 固定格式区使用稳定的网格和最小高度，避免标签、长名称、加载状态改变整体布局。
- 所有新增样式使用 `rpx`；使用 `hover-class` 表达触按反馈，不使用 `:hover`、DOM API 或仅 H5 可用的实现。

## 数据流

1. `index.vue` 在 `onShow` 中保持现有 `loadPageData` 调用。
2. 已登录时继续并发加载活动、我的报名、余额和当前球队信用，再同步未读消息。
3. 页面层构建比赛摘要、年度统计、钱包摘要、信用摘要和加入天数。
4. 页面层通过明确 `props` 将展示数据传给子组件。
5. 子组件发出切换、导航、登录、退出或续费意图。
6. 页面层执行现有 Store、路由、确认框和支付逻辑，并按需要刷新数据。

不引入新的全局 Store，不在子组件中重复请求数据。

## 状态与错误处理

- 首次加载：显示与新布局一致的 `MineSkeleton`。
- 后台刷新或球队切换：保留现有内容，切换控件进入处理中状态，不回退为白屏。
- 未登录：只显示未登录 Hero 和权益预告，不显示伪造余额、信用或比赛数据。
- 无球队或无身份：展示明确空状态，球队管理和续费入口不出现。
- 无比赛：比赛区保留标题和稳定空状态。
- 无信用记录：显示当前信用分和既有默认说明。
- 接口失败：将现有 `errorMessage` 渲染为页面内硬边提示条；已有内容可用时不清空。
- 支付中：续费入口显示处理中并禁用重复提交。
- 取消支付和支付失败：沿用现有 Toast 文案和行为。

## 验证

实现完成后执行：

```bash
bun run type-check
bun run build:h5
bun run build:mp-weixin
```

H5 视觉验收至少覆盖：

- 390×844 移动视口
- 1280×900 桌面视口
- 登录态和未登录态
- 有多个球队和身份的状态
- 无球队、无比赛和接口错误状态
- 切换中与会员支付中状态

交互验收覆盖：编辑资料、登录、退出、球队切换、身份切换、球队管理、全部比赛、比赛详情、账单、消息和会员续费入口。

纯视觉调整不机械新增单元测试。若实现中新增共享展示数据转换或改变关键组件事件契约，则补充针对性测试。

## 验收标准

- “我的”页与首页、比赛详情页形成一致的 Soft Neo-Brutalism 视觉语言。
- 完整功能范围均可见或按现有权限和审核状态正确隐藏。
- 现有业务流程、接口和路由行为没有回归。
- `MineHeroProfile.vue` 的职责被拆分，页面专属组件边界清楚，无子组件直接请求业务 API。
- H5 和微信小程序构建通过，目标视口无文本溢出、遮挡、布局跳动或底部 Tab Bar 重叠。
