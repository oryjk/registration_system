# 场馆组局（venue_hosted）设计

## 目标

新增场馆身份：场馆账号可发布不属于任何球队的比赛，比赛分甲、乙两边，每边可由一支球队占下，也可由散人凑满。已发布的旧版小程序和现有报名不受影响。

## 发起权限（递进）

- 所有登录用户：散人约球。
- 场馆（`users.is_venue`）：散人约球、场馆组局。
- 当前球队的队长、领队：散人约球、自己球队的比赛。
- 一个账号可同时是场馆和队长。场馆由管理后台开通；取消后已发布比赛仍由发布者管理。

## 数据结构

- `users.is_venue BOOLEAN NOT NULL DEFAULT FALSE`。
- `matches.publication_mode` 新增 `venue_hosted`，主队、客队都为空；`created_by_user_id` 为发布者。
- `match_registration_groups.side`（`a` / `b`，可空）。现有比赛为空，行为不变。
- 发布时创建甲、乙两个散人组。球队占边：取消该边散人组，新建该球队的 `guest_team` 组（带 `side`）。退出或移出：取消球队组，重建空散人组。
- 原“同类型有效组唯一”索引只约束 `side IS NULL`；新增索引保证每场每边只有一个有效组。

迁移全部为加法或放宽，可先于新镜像执行。

## 规则

### 占边

- 队长或领队发起，球队状态正常，比赛报名中且在报名时间内。
- 系统分配一个没有有效报名的散人边；没有时报冲突。同一球队不能占两边。
- 占边、退出、移出与报名在同一事务内锁定比赛。

### 报名

- 散人不选边，服务端先排甲边，满后排乙边，已被球队占的边跳过。忽略客户端传入的散人组，保证旧版请求可用。
- 取消报名不做重排；某边人走空后回到可占状态。
- 占边球队的成员不能以散人身份报这场。球队边每次报一人，散人边沿用散人约球的多人规则。

### 退出和移出

- 退出：占边球队的队长或领队。移出：发布者。移出通知该队队长、领队和已报名队员。
- 比赛开始后不能退出或移出。队员报名随组失效，不涉及退款。

### 管理

- 发布者修改、取消、录比分、结束比赛；占边球队队长不能结束比赛。
- 两边都达到最低人数才算成行。
- 球队边队员沿用球队比赛的参与星数；散人无球队星数；场馆没有队长组织积分。

### 费用

只允许免费、线下 AA、人均金额（赛后），不支持预付和队费扣除。

## 接口（只增不改）

- 用户响应新增 `is_venue`；管理端新增设置、取消场馆。
- 报名组响应新增 `side`。
- 新增占边、退出、移出接口。
- 比赛列表未传 `publication_modes` 时默认排除 `venue_hosted`。

## 客户端

- 小程序（仅微信端）：按身份显示发起入口，新增场馆组局发布页和详情页两边状态，大厅白名单加入新类型。
- 管理后台：用户场馆开关，比赛列表和详情正确显示新类型。

## 上线顺序

迁移 → 后端 → 管理后台（开通测试场馆）→ 小程序体验版验收 → 提审。

## 测试

后端 TDD 覆盖占边权限、自动排边、并发、重新开放；现有四种比赛类型的报名测试继续通过；不传类型筛选的列表不返回新类型；旧版客户端读取详情和报名不报错。

## 不做

在线预付、场馆提现和退款、散人选边、后台代发、场馆主页。
