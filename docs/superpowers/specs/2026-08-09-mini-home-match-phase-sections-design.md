# 小程序首页比赛阶段分区设计

## 背景

小程序正在从旧后端迁移到 Go 后端。Go Match 模型只有比赛状态、开始时间和结束时间，没有独立的报名截止时间。当前约定为：比赛开始即停止报名，比赛结束时间到达即视为实际结束，即使数据库状态尚未及时更新。

首页需要围绕用户相关比赛形成三个清晰区域，并移除已有的“约队机会”区域。约队发布、匹配和管理继续由专门的约队页面承载。

## 目标

- 首页比赛数据只读取 Go App API，不再调用旧的活动、约队或系统配置接口。
- 通过统一的前端分类规则，将比赛分为待报名、进行中和已结束三种展示阶段。
- 新增“进行中的比赛”和“已结束的比赛”区域，每个区域首页最多展示 2 场。
- 两个新增区域均按时间倒序排列，并提供“更多”入口查看该阶段的完整列表。
- 首页和二级列表复用同一套阶段分类、排序和卡片展示规则。
- 保持现有 Soft Neo-Brutalism 视觉语言，并继续复用比赛卡片组件。

## 非目标

- 不新增 `registration_deadline` 字段。
- 不新增 Go HTTP 路由或修改现有 API envelope。
- 不在本次任务中实现约队页面的新功能。
- 不依赖旧后端接口或旧后端状态定义。
- 不通过定时任务自动回写 Match 数据库状态；本次只计算前端展示阶段。

## 数据来源

### 首页摘要

使用现有接口：

```text
GET /api/v1/app/matches/home
```

前端合并响应中的 `action_items` 与 `ended_items`，按比赛 ID 去重，然后使用统一分类函数重新计算 UI 阶段。后端数组名称只表示查询来源，不直接等同于最终 UI 阶段。

### 二级列表

使用现有接口：

```text
GET /api/v1/app/matches?scope=mine&page=<n>&page_size=<size>
```

二级页沿用 Go 列表分页能力，加载用户相关比赛后使用同一分类函数筛选目标阶段。页面路由参数决定展示阶段：

```text
/pages/home/matches/index?phase=ongoing
/pages/home/matches/index?phase=ended
```

不传 `phase` 时保留待报名列表的默认行为。

由于 Go 列表按完整比赛集合分页，而 UI 阶段由前端计算，二级页必须保存源分页游标和 `total`。每次加载后先追加、去重、分类；如果当前批次没有目标阶段数据但源列表仍有下一页，则继续请求下一页，直到获得可展示数据或消费完源列表。用户继续上拉时重复该过程，最终能够展示该阶段的全部比赛，而不是只过滤第一页。

## 统一阶段规则

分类函数接收 Match、当前时间，返回 `upcoming | ongoing | ended | excluded`。优先级必须固定：

1. `status == cancelled`：`excluded`，首页和上述二级列表均不展示。
2. `status == ended`：`ended`。
3. `now >= end_time`：`ended`，覆盖未及时更新的 `registering/ongoing` 状态。
4. `start_time <= now < end_time`：`ongoing`，表示报名已结束、比赛尚未结束。
5. `now < start_time`：`upcoming`，表示仍处于赛前待处理阶段。

边界采用左闭右开区间：到达 `start_time` 的瞬间进入 `ongoing`，到达 `end_time` 的瞬间进入 `ended`。

## 排序与数量

- 待报名区域继续按产品现有规则展示近期需要处理的比赛。
- 进行中区域按 `start_time` 倒序，最近开始的比赛排在前面，首页截取前 2 场。
- 已结束区域按 `end_time` 倒序，最近结束的比赛排在前面，首页截取前 2 场。
- 去重发生在分类和排序之前，避免同一比赛同时出现在 `action_items` 与 `ended_items` 时重复展示。
- 二级页不执行首页的 2 场截断，展示该阶段全部已加载比赛，并沿用相同倒序规则。

## 首页结构

首页内容顺序调整为：

1. Hero
2. 最近要处理的比赛
3. 进行中的比赛
4. 已结束的比赛
5. 底部导航

删除“约队机会”标题、列表、空状态、请求和相关首页状态。约队入口不在首页保留替代按钮，用户通过底部“约队”页进入专门流程。

### 区域行为

- “进行中的比赛”与“已结束的比赛”仅在登录后展示。
- 区域有数据时显示最多 2 张卡片；无数据时保留紧凑空状态，避免用户误以为加载失败。
- 有对应阶段数据时显示“更多”，点击进入带 `phase` 参数的二级页。
- 卡片始终允许进入比赛详情。
- `ongoing` 和 `ended` 卡片不显示“去报名”，主动作统一为“查看比赛”。
- 进行中卡片显示“报名已结束”阶段提示；已结束卡片显示“比赛已结束”。

## 组件与状态边界

### API 层

新增小程序 Go Match API 封装，负责 `/matches/home` 和 `/matches` 请求及 DTO 类型，不在页面中拼接 URL 或解释 Go envelope。

### 分类与视图模型

新增纯函数模块，职责包括：

- Match UI 阶段计算。
- 首页响应合并和按 ID 去重。
- 各阶段排序。
- Go DTO 到比赛卡片 ViewModel 的转换。

该模块不访问网络、不读取全局状态，首页与二级页共同使用。

### 页面层

首页只负责加载、刷新、登录态、区域编排和导航。二级页只负责分页加载、按路由阶段筛选和详情导航。

### 视觉组件

继续复用现有比赛列表和卡片视觉。卡片 ViewModel 增加明确的展示模式或等价字段，例如阶段说明、动作文案、是否显示报名进度、是否允许进入详情。业务阶段判断不写进 Vue 模板。

## 加载与错误处理

- 未登录时不请求受保护的 Go Match 接口，保留登录引导。
- 首页请求失败时显示首页比赛区域错误状态，并允许下拉刷新重试。
- 某个阶段为空不视为错误。
- 二级页首次加载失败显示可理解的错误信息；后续分页失败保留已加载内容并允许重试。
- 二级页以 Go 列表的 `total` 判断源数据是否加载完成，不能以某一批筛选结果为空来提前结束分页。
- 当前时间在每次页面加载或 `onShow` 时重新获取，返回首页后重新分类，避免跨越开始或结束时间后阶段仍旧陈旧。

## 测试与验证

### 前端逻辑测试

分类纯函数至少覆盖：

- 已取消比赛被排除。
- 显式 `ended` 状态优先进入已结束。
- `registering/ongoing` 但 `end_time` 已到达时进入已结束。
- 当前时间等于 `start_time` 时进入进行中。
- 当前时间等于 `end_time` 时进入已结束。
- 合并首页两个数组后按 ID 去重。
- 进行中按开始时间倒序，已结束按结束时间倒序。
- 首页两个新增区域各截取最多 2 场。

### 页面验证

- H5 类型检查和构建通过。
- 微信小程序构建通过。
- Mock/测试数据同时包含待报名、进行中、时间已结束但状态未更新、显式已结束和已取消比赛。
- 人工确认首页三个区域顺序、空状态、“更多”导航、二级列表和详情跳转。

## 验收标准

- 首页不再出现“约队机会”区域，也不再发起相关请求。
- `start_time <= now < end_time` 的非取消、非结束比赛出现在“进行中的比赛”。
- `now >= end_time` 的比赛即使状态仍为 `registering/ongoing`，也出现在“已结束的比赛”。
- 两个新增区域首页各不超过 2 场，且时间倒序正确。
- “更多”分别进入正确的二级阶段列表，列表使用相同分类规则。
- 所有新卡片保持现有 Soft Neo-Brutalism 风格，且进行中和已结束比赛可查看详情但不能继续报名。
