# Go 管理后台 ProComponents 视觉改造设计

## 背景

`registration_system_backend_fe_go/` 是只对接 Go 新后端的 React 管理后台。当前技术栈为 React 19、Vite、React Router 和 Ant Design 5，已经具备管理员认证、比赛管理、球队管理、场馆管理员管理及接入状态页面。

当前界面能够完成业务操作，但页面大量直接组合 Ant Design 的 `Table`、`Form`、`Modal`、`Drawer` 和 `Descriptions`，页面标题、筛选区、表格区和表单区依靠约 700 行全局 CSS 维持一致性。视觉表现仍接近通用 Ant Design 模板，且存在直接覆盖 `.ant-*` 内部选择器的维护风险。

## 目标

- 将管理后台塑造成安静、专业、高效率的赛事运营工作台。
- 保持高信息密度，强化扫描、筛选、比较和重复操作效率。
- 统一页面标题、筛选、表格、分页、详情和表单交互。
- 用 Ant Design Token 和 ProComponents 的公开能力减少内部样式覆盖。
- 保留现有 API、DTO、认证、权限、路由和业务行为。
- 同时保证桌面与移动视口可用。

## 非目标

- 不升级到 Ant Design 6。
- 不迁移到 Ant Design Pro 完整脚手架或 Umi Max。
- 不改动 Go 后端接口、数据库结构或权限规则。
- 不重写认证、请求层和 React Router 路由。
- 不将运营后台改造成营销站、卡片瀑布流或低密度大屏。

## 版本决策

- 保留 `antd 5.29.3` 和 React 19。
- 保留 `@ant-design/v5-patch-for-react-19`。
- 引入 `@ant-design/pro-components 2.8.10`。
- 该版本的 peer dependencies 支持 `antd ^4.24.15 || ^5.11.2` 和 React `>=17`，与当前项目兼容。
- Ant Design API 和 Token 查询必须针对 `5.29.3`，不能直接使用 v6 专属能力。

## 架构边界

```text
现有 API/Auth/Router
        |
        v
现有 AppShell 导航与权限菜单
        |
        +--> PageContainer：页面标题、说明、返回与主操作
        +--> ProTable：列表、筛选、分页、刷新与行操作
        +--> ProForm：独立页面表单与字段编排
        +--> ModalForm/DrawerForm：轻量创建、编辑与详情操作
        |
        v
ConfigProvider 全局 Token + 组件 Token + 少量业务布局 CSS
```

现有 `src/api/`、`src/types/`、`src/auth/` 和路由定义保持边界不变。ProComponents 只进入布局和页面展示层，不承载业务规则，也不直接发起未经 API 层封装的请求。

## 视觉体系

### 色彩

- 深绿色继续作为导航和品牌基色。
- 荧光黄只用于主操作、在线状态和少量关键强调，不作为大面积背景。
- 页面背景使用中性浅灰绿，内容面使用白色或轻微层级差。
- 错误、警告、成功状态继续使用语义色，不用品牌色替代业务状态。
- 通过 CSS 变量和 ConfigProvider Token 管理颜色，不散落硬编码值。

### 排版与密度

- 中文信息为主，移除无业务价值的英文 kicker；确需保留时只作弱化辅助。
- 页面标题保持紧凑，表格和筛选区优先支持快速扫描。
- 表单标签、帮助文本和错误文本形成稳定层级。
- 不使用超大标题、巨型留白和营销式构图。

### 形态

- 圆角保持克制，卡片和工具面不超过 8px。
- 减少大面积硬边框，使用背景层级、分隔线和局部阴影表达结构。
- 不在卡片内继续嵌套卡片。
- 图标使用现有 `@ant-design/icons`，不新增手绘 SVG。

## 页面改造

### 应用框架

- 保留现有 `AppShell`、React Router 和权限菜单逻辑。
- 统一侧栏选中态、折叠态、移动抽屉和顶部账号区。
- 顶栏不重复展示每个页面已经表达的标题，减少垂直空间占用。
- 页面内容使用一致的最大宽度和响应式内边距。

### 登录页

- 保留真实球场图片作为第一视口品牌信号。
- 提高遮罩对比度和文字可读性，收敛装饰性英文文本。
- 登录表单保持单一主操作，错误提示靠近表单，不改变认证流程。

### 仪表盘

- 从开发者视角的路由清单调整为运营视角概览。
- 第一层展示服务状态、比赛数量、球队数量和需要处理的状态；没有真实接口的数据不得伪造。
- 暂无统计接口时只展示可由现有接口可靠计算的数据，并保留接入状态页承载技术信息。

### 比赛列表

- 使用 ProTable 的服务端分页模式。
- URL 保存关键词、状态、当前页和页大小。
- 主要操作固定为发布比赛；行操作按查看、编辑、取消或永久删除的权限顺序呈现。
- 移动端保留比赛名称、状态和操作，隐藏次要列。

### 球队列表

- 使用 ProTable，但保留现有全量加载和前端筛选，因为后端尚未提供分页契约。
- 创建和编辑迁移到 ModalForm。
- 详情继续使用 Drawer，信息采用清晰的字段分组，不嵌套卡片。
- 删除约束和错误信息保持现有行为。

### 场馆管理员列表

- 使用 ProTable 的静态数据模式，不伪造分页。
- 创建管理员迁移到 ModalForm，密码确认与字段校验保持不变。
- 非超级管理员的 403 页面保持权限边界，不用前端隐藏替代后端授权。

### 比赛表单

- 保留独立路由，使用 ProForm 编排“比赛信息”和“时间与场地”两个区段。
- 保留线上约队、线下已约和散人模式的条件字段。
- 保留搜索主队、快速创建不存在球队以及提交前确认流程。
- 底部操作区在长表单滚动时保持可达，移动端按钮不溢出。

### 比赛详情与接入状态

- 比赛详情使用统一 PageContainer、状态摘要和报名组表格。
- 接入状态页继续展示认证与 API 技术信息，与运营仪表盘分离。

## 数据与状态流转

```text
URL 查询参数
    -> 页面解析筛选和分页
    -> src/api 调用 Go 管理端接口
    -> ProTable/ProForm 展示 loading、data、error
    -> 用户操作成功后刷新当前查询
    -> URL 和页面状态保持一致
```

- 比赛列表以服务端返回的分页结果为准。
- 球队和管理员列表在后端分页落地前使用本地数据源。
- 筛选、分页和搜索不得绕过 `src/api/` 直接拼接请求。
- 刷新页面、浏览器返回和复制链接后应恢复列表状态。

## 错误与反馈

- 页面加载失败使用页面级 Alert，并提供明确的重试动作。
- 表单校验错误显示在字段附近。
- 创建、编辑、取消和删除成功使用轻量消息反馈。
- 删除、取消比赛和永久删除继续使用二次确认。
- 权限错误保持 403 语义；网络和业务错误使用 API 层提供的真实消息。
- loading、empty 和 error 状态必须占用稳定空间，避免布局跳动。

## 响应式与可访问性

- 主要验证视口为桌面 `1440x1000` 和移动 `390x844`。
- 移动端隐藏次要表格列，行操作收进菜单或紧凑图标组。
- 页面标题与主操作在窄屏换行，不互相遮挡。
- 图标按钮保留 `aria-label` 和 Tooltip。
- 表单标签与控件保持可关联，焦点态和键盘操作不能被自定义 CSS 破坏。
- 色彩对比不能只依赖颜色表达状态。

## CSS 与组件约束

- Theme 优先级为：全局 Token、组件 Token、公开 `classNames/styles`、业务布局 CSS。
- 逐步移除对 Ant Design 内部 DOM 和宽泛 `.ant-*` 选择器的依赖。
- 不建立一个承载所有页面差异的巨型组件。
- 可复用边界限定为页面容器、状态显示、列表操作和表单反馈，不抽象业务字段本身。

## 验证策略

- `bun run type-check`
- `bun run lint`
- `bun run build`
- 使用 Playwright 验证登录、比赛列表、比赛表单、比赛详情、球队列表和管理员列表。
- 桌面和移动视口分别截图，检查文字溢出、控件遮挡、表格操作和抽屉/弹窗尺寸。
- 运行现有管理员比赛流程，确认改造没有改变接口、权限和提交 payload。

## 实施顺序

1. 安装 ProComponents，建立 Token 与页面容器基础。
2. 调整 AppShell、登录页和全局响应式规则。
3. 改造比赛、球队和管理员列表。
4. 改造比赛表单、比赛详情、仪表盘和接入状态页。
5. 删除失效 CSS，执行完整类型、lint、构建和 Playwright 验证。

## 风险控制

- ProComponents 不负责改变 API 参数结构；分页模式按各接口真实能力分别配置。
- 不同时升级 antd 6，避免视觉改造与组件迁移风险叠加。
- 每类页面改造后立即进行桌面和移动验证，避免最后集中处理响应式问题。
- 保留现有 E2E 关键选择器或同步更新为稳定的可访问性选择器。
