# 年度荣誉分享与海报背景

用户已明确要求「一起实现并发布完整分享功能」，包括三款背景选择、荣誉分享与扫码后的加入/创建球队入口。本期不接入收费或自定义上传。

## 体验

- 队员从当前球队统计页或自己的头像预览进入「分享我的荣誉」。其他人的头像不提供代分享。
- 后端取得当前球队、自己的头像昵称、年度积分/排名、付费会员标记。皇冠只代表该球队付费会员，前三名称号独立显示，零分不显示称号；不显示积分算法。
- 海报提供绿茵日常、荣耀金、夜场聚光三款免费背景，预览即时切换并记住选择。图片从 MinIO 下载，不占小程序主包。数据与小程序码在客户端叠加，姓名/球队名称长度受控换行，头像失败显示首字。
- 发给朋友使用微信原生分享卡片，打开荣誉落地页。保存海报写入相册，可用于朋友圈；二维码保留真实码的完整边界，不生成示意码。
- 积分与荣誉在打开页面时加载，保存海报使用页面已展示的数据，不再次查询积分。打开页面或切换背景时提前准备海报，封面与海报复用图片路径；再次进入页面才刷新统计。接收者页面的卡片间距由页面外层容器控制，采用通用 `--ui-card-list-gap`。
- 用户端统一以「星」展示积分单位：海报为「年度参与星」，头像预览为「年度星数」，排行榜显示累计星数。数值、计算规则与接口字段不变。
- 微信好友及朋友圈分享链接携带所选背景 id，接收者按链接展示相同预设背景，不覆盖接收者自己的背景偏好。旧链接或未知 id 使用默认背景。
- 荣誉落地页显示分享者所属球队与指定年度实时统计；提供「加入这支球队」和「创建我的球队」。已在队显示查看球队，入队继续使用现有口令、资料完善与登录规则。创建入口遵守现有审核态隐藏规则。

## 链路与权限

- 新增 `team_honor_shares` 表，只存 UUID、team_id、user_id、score_year、created_at；每队员每球队每年唯一。22 字符 base64url UUID 是分享码，适合微信 scene 长度。没有固定七天过期；分享者离队、账户冻结或球队不可用时不再展示该链接。
- `POST /teams/:id/honor-share` 只为当前登录者、在队成员创建自己的分享，年份由服务端北京时间决定。`GET /honor-shares/:code` 解析已创建的码，返回公开展示字段和访问者在队状态，不返回手机号、真实姓名、余额或入队口令。
- `POST /honor-shares/:code/mini-code` 只允许分享者为自己生成码，接受 release/trial/develop，后端调用微信稳定 access_token 和无限小程序码接口，并保存至 MinIO。错误不会被当成图片保存，失败时朋友分享仍可用。
- 小程序码进入已有首页，由新版本首页读取 scene 后跳转荣誉页。开发版用 develop，体验版用 trial，正式版用 release；旧正式版扫描时仍进入首页，完整荣誉页需要新版本正式上线。
- 既有邀请码路由、字段、权限、七天有效期均不改变。新表为加法迁移，与线上旧镜像兼容。

## 背景及后续扩展

三款背景原图和提示词保留在 `docs/design-assets/honor-posters/v1/`；客户端使用 `v2/` 的 1024×1536 压缩 JPEG 和 256×384 缩略 JPEG。只加载所选高清背景，选择区加载缩略图，小程序预览与导出共用可验证的本地文件缓存，H5 使用 immutable HTTP 缓存。旧 PNG 对象不删除。MinIO 对象使用内容哈希且已校验公网 SHA256。目录元数据含稳定 id/version/source/access/url 与文字颜色。此次 access 全为 free。后续精品背景由服务端权益校验，自定义图片由上传接口校验文件/尺寸并确定归属；不能以修改客户端 free 标记获得权益。付费和上传入口本期不展示。

## 验证与交付

后端应用权限、年份、码解析，仓储真实年度查询和唯一分享记录、HTTP 响应及微信返回处理需测试。前端检查路由参数、状态清理、分享自己的权限、背景持久化、失效码与相册失败；执行类型检查、生产小程序构建、H5 视觉检查。提交 push 后执行 jd check/migrate/backend 发布并核验健康，再用统一 mp:release 上传开发版。公众平台正式审核发布不由开发上传自动完成。
