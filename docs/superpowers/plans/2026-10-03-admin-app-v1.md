# 移动管理 App 首版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 Android/iOS Flutter 管理 App，完整覆盖登录、比赛与报名查询、球队成员管理、会员及人工队费操作。

**Architecture:** 采用按 feature 组织的 domain/data/application/presentation 分层、构造函数注入及 ChangeNotifier controller。Go 协议在 data 层映射，主题与复用交互组件独立，App 层统一协调会话和刷新。各任务共用契约；这是一套客户端的连续交付，所有任务完成后才算首版完成。

**Tech Stack:** Flutter 3.44.2、Dart 3.12.2（已检测）；Material 3、http、shared_preferences、flutter_secure_storage；flutter_test 和 HTTP mock。依赖由兼容解析后锁定，不添加大型状态管理框架。

**Spec:** [2026-10-03-admin-app-v1-design.md](../specs/2026-10-03-admin-app-v1-design.md)

## Global Constraints

- 仅恢复移动管理客户端和相应文档，不恢复 Rust/旧 Vue 项目，不调整现有 Go API 和数据库 schema。
- Go 管理接口为 `/api/v1/admin`，统一响应 `{ code, message, data }`，成功 `code = 0`。
- release API base 为部署文档核实的 `https://oryjk.cn:82/regist-v3`，以 `ADMIN_API_BASE_URL` 的 dart-define 覆盖；管理前缀与 base 分开，健康检查为 base 下 `/health`。
- 深色为初始主题，提供浅色并持久化偏好；底部导航为“工作台 / 比赛 / 球队 / 我的”。
- 点击热区至少 48；布局覆盖 360/390/430 宽度、横屏、安全区、键盘、长名称、空头像、长错误、文本放大至 2 倍。
- 金额为整数分，单笔充值/消费上限为 1,000,000 分（10,000 元）；付费会员标记只提交 `is_paid_member`。
- 具体时刻 UTC 存储和传输，输入与展示统一北京时间；纯日期为 `YYYY-MM-DD`。
- 401 清空会话与受保护导航；403 保留会话；不自动重试未核实幂等的写请求。
- 安全存储保存 token 和待确认资金动作，密码不持久化；普通偏好不存 token。待确认动作按环境和管理员隔离。
- 创建比赛仅开放 `offline_confirmed`、`online_team`、`online_individual`；已有 `online_pickup` 可查看及按后端规则编辑。
- 报名管理仅提供花名册查询与状态展示；用户管理、管理员配置、系统设置、球队约战申请与比赛结算不在首版范围。
- 不向线上业务表写测试数据；未执行的构建及真实接口验收写明原因。

## Review Focus

1. 安全存储读取/写入/删除失败：不得进入假登录状态或继续以旧账号操作；资金动作持久化失败不能发请求（任务 1、3、8）。
2. 旧会话请求在新账号登录后才返回 401：不得使新会话退出，旧数据不得覆盖新账号（任务 2、3、9）。
3. 首次获取成功、操作成功后刷新失败：保留正确的成功反馈与可重试刷新，不引导重复写入（任务 5、7、8）。
4. 已删除球队/成员、未知枚举或 nullable 字段：查询能解释缺失，未知状态不得开启危险动作（任务 4、6、7）。
5. 未确认队费动作重启后存在、金额被修改或幂等冲突：保留原 key/payload，禁止自动重放或另起同类请求（任务 8、9）。
