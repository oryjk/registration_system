# 时间与业务日期约定

管理端和小程序服务国内赛事。时间展示、输入、日历分组、日期筛选统一使用北京时间（`Asia/Shanghai`），不依赖服务器、浏览器或手机的本地时区。

## 具体时刻

- 比赛开始/结束、报名起止、注册/加入球队、最近活跃、会员到期、流水入账等均为具体时刻。
- 后端时钟、数据库连接会话使用 UTC。既有 `timestamp without time zone` 列按 UTC 墙钟保存，写入前必须转换成 UTC；此次不改旧列类型。
- API 使用 RFC3339，携带 `Z` 或明确偏移。新代码返回 UTC `Z`；不得把具体时刻输出为无时区字符串。
- 管理端和小程序通过各自的公共时间工具转换为北京时间。禁止直接截取 ISO 字符串作为展示日期、日历归属或时分。
- 兼容旧接口时，无时区的后端时间字符串按既有 UTC 存储约定解析。用户输入的无时区日期/钟点属于北京时间，由表单工具明确解释；两种来源不能共用模糊的本地解析。

例如，同一时刻 `2025-12-31T16:30:00Z` 应在所有设备显示为北京时间 **2026-01-01 00:30**，并归入 2026 年 1 月 1 日。

## 纯日期

- 手工收款日期 `received_on`、出勤筛选的 `startDate` / `endDate` 等使用 `YYYY-MM-DD`，表示北京时间下的日历日期。
- 纯日期使用数据库 `date` 或日期字符串；它没有时分和时区，不转成 UTC 再展示。
- Go 的 `time.Time` 若用于承载日期参数，日期分量才是有效语义，不得当作实际午夜时刻。
- 同一记录可以同时有收款日期和录入/入账时刻；日期与时刻分别遵循各自约定。

## 按日查询与日历

- 出勤统计的开始日包含北京时间零点，结束日包含整天：换算为 UTC 后使用 `[开始日零点, 结束日次日零点)`。
- 大厅 `date_start` 保留已有接口语义：一个带时区的具体时刻起的 24 小时窗口。前端将所选北京时间日期的零点序列化为 UTC 后发送。
- 日历格子、月份、年份、“今天”、展示标签和统计筛选应使用同一个北京时间日期键。
- 相对时间、倒计时、是否到期等按真实时间差计算，无需加减八小时。

## 转换入口与验证

- 管理端使用 `registration_system_backend_fe_go/src/utils/` 中的公共格式化和表单时间工具。
- 小程序使用 `registration_system_mini/src/utils/datetime.ts`，不要求手机支持完整 `Intl` 或新增依赖。
- 时间选择器的日历 Date 或挂钟字符串仅用于表达所选日期/钟点；提交时重新解释为北京时间，转换成 UTC。真实时间戳不做展示偏移后直接提交。
- 回归覆盖北京时间零点、跨月/跨年、结束日边界、纯日期、旧无时区字符串，以及 UTC/洛杉矶/上海设备时区下相同显示和提交结果。
- 保留旧小程序的路由、字段名称和类型，不修改已部署数据库结构。
